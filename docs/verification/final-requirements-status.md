# Final Requirements Status

Updated: 2026-07-03

This file records the current board-level completion status against the teacher's
highest final requirements.

| Requirement | Current status | Notes |
| --- | --- | --- |
| RC522 reads UID stably | Done | Complete firmware has read real UIDs and reports healthy RC522 diagnostics. |
| Account header can be issued | Done | UID, SID, points, card type and CRC are written to sector 0 block 1. |
| Image data can be issued | Done | Real-card complete issuing flow is implemented and confirmed: account header, 24 portrait blocks, 10 name blocks, 10 department blocks and `UPDATEIMG`. Firmware reselects the card, reauthenticates the target sector and verifies each image block by readback. |
| Empty/bad/unissued card is invalid | Done | CRC and UID consistency checks reject invalid card data. |
| Repeated card swipe is detected | Done | Recent UID anti-repeat path is implemented and validated. |
| Check-in/check-out/in-out modes | Done | Real-card path honors `MODE=1/2/3`: check-in rejects already-inside cards, check-out rejects no-entry cards, and in/out alternates IN/OUT. Host tests cover these cases and the integrated board flow has been confirmed. |
| Out duration and cross-day duration | Done | OUT records compute `DUR` from the latest matching IN timestamp using unsigned seconds subtraction; host tests cover a 23:50 to 00:10 cross-day case. |
| OLED shows time, SID, type, status and result | Done | Attendance result pages use the demo-compatible `SimSun_24` font split across two pages. Page 1 shows time/type and SID; page 2 shows status and result or OUT duration. K3 advances and K2 returns while a detail page is active; detail pages stay visible for 30 seconds. Host display tests cover OK, duplicate, invalid, error, OUT-duration and page switching, and real-card display has been confirmed. |
| LED/buzzer feedback for success/fail/repeat/network | Mostly done | Success, invalid card, duplicate, fault and network-online feedback are implemented. |
| Administrator mode | Done | `card_type=2` administrator cards enter a 120-second on-device setup mode. Normal cards are rejected during administrator mode. K2/K3 select device id or work mode, K4/K5 change values, K1 exits, and K6 saves `/config.bin` then resets. Host NFC/display tests cover entry, rejection, save and timeout, and the real-card administrator flow has been confirmed. |
| Flash storage complete | Mostly done | Attendance records are stored in W25Q128/LittleFS as a CRC-checked 1024-record ring buffer. Host littlefs tests cover full overwrite of oldest records, logical read order, pending-upload scan and upload marking. Board tests appended `SEQ=104/105`, confirmed records after DAP reset, and confirmed config persistence after reset. A physical 1024-record fill test remains. |
| WiFi/networking stage | Mostly done | Firmware starts ESP01S, syncs NTP into RTC, uploads pending records only after ACK, keeps offline records pending, retries after reboot/network recovery, and defers weather while an upload is busy. Firmware now CRC-wraps TCP frames, batches up to three pending records with `UPLOADB`, verifies CRC-wrapped responses, refreshes `BL?` after heartbeat, rejects blacklisted UIDs locally, exposes `NET?` for runtime link diagnosis, and supports OTA download/cache/CRC32 verification into W25Q128. Board retest after flashing verified CRC heartbeat, CRC `BL?`, single CRC upload `SEQ=109`, batch CRC `UPLOADB` for `SEQ=110/111`, server SQLite/API rows, local `UP=DONE` ACK marking and DAP-reset persistence. The requested router network was configured and persisted, but board `NET?` stayed at `STATE=2|TEXT=WIFI_CONNECTING|NTP=0`; Windows scan showed that SSID only as 5 GHz WPA3. Switching to a 2.4 GHz phone hotspot restored networking: `NET?` reached `READY=1|TEXT=TRANSPARENT`, backlog `SEQ=115` uploaded to `UP=DONE`, fresh `SEQ=116` uploaded to server SQLite, and `OTA!` downloaded both the small `stage1-test` package, a full direct-flash `Demo_W25Q128.bin` package and the offset app package used by the bootloader with matching CRC32. Real-card local blacklist rejection still needs a card-present test. |
| Server/Web backend | Implemented, host/runtime verified | One Python process receives heartbeat/uploads, stores SQLite data, serves `/devices`, `/records`, `/blacklist`, `/ota`, supports device/SID/time filters, batch upload, blacklist management, heartbeat online detection, CRC validation and OTA package query/chunk download. Legacy clients use `current.bin`; A/B clients request slot-specific `current_A.bin` or `current_B.bin`. Runtime smoke on 2026-07-03 verified HTTP pages, blacklist POST, CRC heartbeat, CRC `UPLOADB`, CRC `BL?`, device API, filtered records API and OTA query/chunk protocol. Temperature display uses heartbeat `TEMP`; firmware now reports STM32F407 internal temperature and board verification showed `TEMP=40.2`. |
| OTA upgrade | A/B board-validated | Prior single-slot bootloader OTA is board-validated. Current A/B implementation keeps bootloader `0x08000000..0x0800FFFF`, slot A `0x08010000..0x0803FFFF`, slot B `0x08040000..0x0807FFFF`, W25Q128 stores `ota.bin`, `ota.meta` and `bootstate.bin`, app requests the opposite slot with `OTA?SLOT=A/B`, server requires slot-specific packages, and bootloader uses pending/confirmed slot state for rollback. Board validation on 2026-07-03 passed A->B and B->A: slot A downloaded `current_B.bin` with CRC `8F4F3162`, `OTARST` installed and booted `CUR=B`; slot B downloaded `current_A.bin` with CRC `872089CC`, `OTARST` installed and booted `CUR=A`; both reported `INSTALL=3|ERR=0`. |
